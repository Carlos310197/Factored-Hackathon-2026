# 87 · Cross-Root Checks: IAM Wildcards, Log Retention, Security Scan

**Subsystem:** Deployment · **Depends on:** 86 · **Reference:** deployment plan, Task 11 (intent and test cases only)

> *(Rewritten 2026-10-04: everything is Terraform.)* cdk-nag is replaced by `trivy config` over `infra/terraform/`, and the CDK template assertions by a pytest suite that parses the Terraform sources. Conventions: `context/code-standards.md` → Deployment → Terraform.

## Goal

Check every Terraform root for wildcard IAM, 30-day log retention and a clean security scan, and fix or justify what the checks find.

## Read First

- `context/ai-workflow-rules.md` and `context/progress-tracker.md` (always)
- `context/code-standards.md` → Deployment (Terraform conventions)
- `context/architecture-context.md` → Deployment Topology; Access Controls and Secrets → Roles

## Requirements

- **IAM:** every policy is written as `data "aws_iam_policy_document"`, so the check can read it (the existing `jsonencode` policies in `bootstrap/`, `platform/` and `app/` are converted in this unit, with their `terraform test` runs still passing). No action `*` or `<service>:*`. `resources = ["*"]` only for actions in `STAR_OK`, each with a written reason (X-Ray `PutTraceSegments`/`PutTelemetryRecords`, `cloudwatch:PutMetricData` with a namespace condition, `ecr:GetAuthorizationToken`). `bootstrap/`'s `gha-deploy` `AdministratorAccess` attachment is the one listed exception until the role is narrowed (deployment plan #12).
- **Logs:** every `aws_cloudwatch_log_group` has `retention_in_days = 30`, and every Lambda and ECS task writes to a log group declared in Terraform.
- **Security scan:** `trivy config --severity HIGH,CRITICAL --exit-code 1 infra/terraform` passes. Each accepted finding is in `infra/terraform/.trivyignore.yaml` with a `statement` giving the reason.
- **Stateful resources:** every `aws_dynamodb_table` has `lifecycle { prevent_destroy = true }` and `deletion_protection_enabled = true`. The S3 buckets are exempt on purpose: the state bucket is versioned and backed up, and the serving bucket's contents are regenerated by every pipeline run (`force_destroy = true` in `bootstrap/` and `platform/`).

## Implementation

### Files

- Create: `infra/scripts/__init__.py`, `infra/scripts/tf_sources.py` (loads every `infra/terraform/*/*.tf` with `python-hcl2`), `infra/terraform/.trivyignore.yaml`
- Modify: `pyproject.toml` (dev group + `python-hcl2`), any root whose checks fail (fix or add a reasoned exception)
- Test: `tests/test_tf_iam.py`, `tests/test_tf_logs.py`, `tests/test_tf_stateful.py`, `tests/test_trivy_ignores.py`

### Interfaces

- Consumes: every Terraform root under `infra/terraform/`.
- Produces:
  - `tf_sources.load_all() -> dict[str, dict]` (root name → parsed HCL);
  - `STAR_OK: dict[str, str]` in `tests/test_tf_iam.py`, the allow-list with reasons that spec §4.2 refers to.

## Scope Limits

- checks over all roots, plus the fixes or written exceptions they force. No new resources.
- Don't touch files outside this unit's list, except to fix a bug in an earlier unit (with a test).

- Tests carrying the reference task's intent: `test_no_service_wide_actions`, `test_star_resource_only_for_allow_listed_actions`, `test_every_log_group_keeps_30_days`, `test_stateful_resources_are_protected`, `test_every_trivy_ignore_has_a_reason`.
- The subsystem's offline suite still passes.
- `context/progress-tracker.md` is updated, and the unit is committed alone.
